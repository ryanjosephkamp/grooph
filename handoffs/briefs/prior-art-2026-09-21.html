What other loop builders got right, and what grooph should take

Written by the driver session for Ryan. Covers the four articles you attached, the Gas Town repository, and the primary sources behind them. Every recommendation says why, what it costs, and what it does not claim.

How this was done, and what was verified. The four articles are secondary sources from one publisher (explainx.ai). I sent two research agents to the primary sources and read their reports: the Claude of Duty repository (README and the original prompt), Geoffrey Huntley's ralph page, Matt Pocock's Wayfinder document, the LoopX and OpenAI Symphony repositories, and twenty-three documents in the Gas Town repository. The "universal-gauntlet" and "encore" skills have no findable primary source and are treated as unverified. Lloyd, the heartbeat orchestrator, exists only as a Reddit post summarised by the article; I could not read the post itself. No code was changed for this review.

The first finding: grooph was built from this material already

The spec's "lessons that constrain the default graphs" section was written from Gauntlet runs: isolation, an inspectable bar, a ratchet and a stop as the method; sequential ownership beating fan-out on coupled systems; evidence quality gated; unbounded loops needing a brake. Its sources list cites Shumer's repository and the original prompt. So the question for most of what follows is not "should grooph adopt the Gauntlet" but "what do these sources add beyond what is already in the sixteen templates".

Source by source

1. The Gauntlet Loop (Matt Shumer, Claude of Duty)

What it is. One seed prompt: fan out sub-agents per piece, each with a harsh separate critic, blind side-by-side comparison against real Call of Duty frames, "loop until perfect". The repository's own honest assessment: critic scores rose from 3.59 to 5.05 out of 10 across rounds, and in every blind A/B every critic picked the real game. No budget, iteration cap or exit condition exists in the prompt. The process note is the most valuable line in the repository: three rounds of six parallel owners moved the score by 0.46 and left more frame-ruining defects than they started with; one sequential pass with a single owner per coupled concern moved it by 1.00 and cut defects from 66 to 26.

What it adds beyond grooph. Three things. The lead decomposes the goal into pieces and each piece gets its own builder-critic pair; grooph's taste-polish polishes one artifact with one owner. The critic's method is a blind A/B with labels stripped, which grooph's critic briefs do not spell out. And the harness around the run mattered as much as the loop: an architecture contract file the agents worked against, a per-pixel diff that fails on any change, and captures made in isolated pages so they were reproducible.

Verdict. adapt Add a composite template, gauntlet-decomposed: a planner decomposes along real seams and writes the pieces with an owner and a reference each; a human approves the decomposition; an outer loop takes one piece per round with taste-polish as its inner loop, so coupled pieces run in sequence by design; an integrator; a final blind comparison. Add the blind A/B method to the reference-critic brief in taste-polish. Keep "until perfect" out, as the spec says.

2. The ralph loop (Geoffrey Huntley)

What it is. A bash loop that pipes the same prompt file into a fresh agent process forever. The discipline, not the loop, is the invention: a new context every pass, anchor files (the prompt, an agent file the loop may append learnings to, a specs folder, a prioritised fix plan), one item of work per pass, commit and tag on green. There is no stopping rule on the page; the human is the brake.

What it adds beyond grooph. grooph's grind-loop already has fresh isolation and a test check. What ralph adds is the plan file as the unit of work: pick the top item, do only that, mark it done, commit. That is a task-list bar the builder ratchets through.

Verdict. adopt Add ralph-loop as a grind-loop variant with a {{plan-file}} slot, a "one item per round" brief, commit on green, and stops the original lacks: diminishing returns on a repeated failure, a round cap, minutes. Cheap, widely recognised, and honest attribution to Huntley.

3. Lloyd, the heartbeat orchestrator (u/croovies), with LoopX and Symphony

What it is. A standing checklist re-run every pulse: check the inbox, scan the app's own logs for silent errors, dispatch a read-only investigator, file findings to a ticket table that has grown past 600 rows, log every pulse including "clean", never ticket routine noise, surface ideas for the human to prioritise rather than act. Symphony (OpenAI) is the same shape with a tracker board as the queue, an in-repo workflow file, caps on concurrent agents and turns per session, and runs that may end at "human review". LoopX keeps objective, gates, todos, evidence and quota in one durable folder.

What it adds beyond grooph. A class of graph grooph has no template for: the pulse, run on a schedule, whose output is a triaged record rather than a change. The safety idea is exactly grooph's policy language (a read-only investigator, a human before any write), so it fits. What does not fit is scheduling: grooph never runs agents, and the harness already has /loop, /schedule and cron.

Verdict. adapt Add patrol-pulse: a scan check, a read-only investigator, a ticket writer that owns only the ticket store the slot names, and a human gate to prioritise; one pulse is one run, and the run list is the pulse log. Add a target-doc section on running a package on a schedule. Decline making grooph the scheduler or the memory store; the memory is a file or database the project owns and the graph names.

4. Gas Town (Steve Yegge)

What it is. A Go supervisor that runs many Claude Code sessions as named workers in isolated worktrees: a Mayor coordinates, a Witness monitors and respawns, a Refinery is the merge queue, polecats do the work, a Deacon patrols, dogs do maintenance. Work is beads (issues) grouped into convoys; workflows are TOML formulas with steps and dependencies; all state lives in a Dolt database with git export. Done is self-declared by the worker; verification lives in the merge queue (batch then bisect, test and lint gates). Brakes are supervisory, not budgetary: three crashes escalate, unacknowledged escalations bump severity, and the scheduler doc says there is no cost or token budget. Patrols loop forever by design. MIT, 18k stars, main branch quiet since July.

What it adds beyond grooph. Four ideas map cleanly. A formula is already a graph document (steps with needs), so the two tools agree on the shape. The merge queue as a first-class node with batch-then-bisect is a better merge gate than grooph's human-gate-plus-irreversible-node. The Witness rule "never implement code directly" is a role constraint worth encoding as a policy. And a "done-intent" marker written before the done step makes a crash mid-completion recognisable, which grooph's run folder could copy. What does not map: a worker pool whose size is chosen at runtime, the daemon as a persistent process, patrols with no exit, event-driven mail, and querying dead sessions. Those are runtime features, and grooph has no runtime by decision.

Verdict. adapt Add a merge-queue fragment (integration check, bisect-or-reject back edge, human gate, land). Add a mayor-and-polecats template with a fixed number of workers fed from a convoy file, a witness that only monitors, the merge-queue fragment and an overseer gate, and say plainly in its text that one run is one convoy, not a town. decline A pool node with runtime cardinality and any persistent-daemon semantics: the spec's lesson on swarming coupled work and decision 0001 (no runtime) both argue against, and no run so far has needed them.

5. Loop engineering as a discipline (Steinberger, Cherny, the guide)

What it is. The framing: stop prompting agents, write the loop that prompts them; a loop is cron plus a decision-maker; a loop needs something that can say no; anchor intent in files; cap iterations, detect no progress, cap spend; skills are the reusable asset inside loops. The guide's loop contract names trigger, scope, action, budget, stop and report.

What it adds beyond grooph. grooph is a design tool for exactly this discipline, and its stops already match the three hard stops. Two gaps in the contract: trigger (harness-level, covered by the scheduling section above) and report (grooph's final note and progress file are the report, but nothing says where it goes). And the guide's strongest practical point, that a loop calling named skills compounds while a loop that re-derives everything does not, has no expression in a grooph node today.

Verdict. small changes Let a node name the skills it may use, mapped to the agent file if the harness supports it (verify against the current subagent frontmatter before building). Say in the brief where the report goes. Nothing structural.

6. Andrew Ng's three loops

What it is. The inner agentic loop on a minutes clock, the developer's steering loop on hours, the external feedback loop on days. Add evals when the same failure repeats. Prefer "context advantage" over "taste" as the reason the human stays in the loop.

What it adds beyond grooph. grooph is the inner loop; its human gates and adopt-or-discard step are the hooks into the middle loop; the outer loop is out of scope. The one transferable mechanism is evals-on-repeat, which the proving ground learned independently: a loop only loops when the critic holds cases the builder cannot see. A critic that turns each finding into a permanent case makes the bar grow across rounds.

Verdict. candidate An evals-ratchet variant of review-gate where the critic appends each finding as a case to an evals file the builder must keep passing. Prove it before shipping; it may turn out to be a brief change to review-gate rather than a template. Change the human-gate wording so the question asks for the context the model lacks, which is what Ng says the human is there for.

7. Wayfinder (Matt Pocock) and the community skills

What it is. A planning skill for work too big for one session: breadth-first questioning closes decisions into a map with a "fog of war" section, typed tickets, and a hand-off to spec and tickets. The "answer key up front" fix for the Gauntlet is a community modification of it described in a video, not the primary document. The "universal-gauntlet" and "encore" skills have no findable source.

Verdict. no template The moment Wayfinder serves is before a graph exists, and the design skill deliberately asks at most three questions. Fold one sentence into the skill: when the ask is fuzzy, recommend spec-then-loop and tell the user to close their decisions first. Cite Wayfinder as an example of how.

Recommendations, with justification and cost

Each is scoped so it fits one slice under the existing protocol. Costs are rough; "spend" means proving runs under the ledger.

A1 · credits on templates

Add an optional credits list to the template block (name, URL, what was taken), print it on the template page, in the index and in the write-ups, and fill it for taste-polish (Shumer, Claude of Duty), ownership-not-swarm (the Claude of Duty process note), spec-then-loop (the answer-key fix, cited as a community modification of Pocock's Wayfinder), and every template added from this review. Why: you asked for attribution; it is cheap; and a library that names its sources is easier to trust. Cost: a docs-and-patterns slice, no spend.

A2 · four templates from prior art

ralph-loop, patrol-pulse, gauntlet-decomposed, merge-queue (fragment), each proved in the proving ground before it ships, as decision 0009 requires. Why: each covers a shape the sixteen do not (a plan-file ratchet, a scheduled pulse, a decomposed reference-polish, a real merge queue), and each has a recognisable name people will search for. Cost: one template slice plus about $15 of proving spend.

A3 · the elaborate one: mayor-and-polecats

A fixed-size worker set fed from a convoy file, a monitor that never implements, the merge-queue fragment and an overseer gate; the text says what it is not. Why: it answers your "are the templates too small" question with a real organisation-shaped graph, and it is the honest way to credit Gas Town. Cost: a template slice after A2, about $10 to $15 to prove; it will be the most expensive run per round in the library.

A4 · blind A/B in the reference critic

taste-polish's critic brief says: compare labels-stripped captures side by side in random order and report which is better and why, before listing gaps. Why: it is the Gauntlet's actual method and grooph's brief only implies it. Cost: one pattern edit and a re-proof (about $3).

A5 · a scheduled-run section in the target doc

How to run a package under /loop, /schedule or cron; each pulse is a run; the run list is the pulse log; the memory store is the project's file the graph names. Why: patrol-pulse is meaningless without it, and Lloyd, Symphony and Gas Town all live on a schedule. Cost: docs only.

A6 · skills on a node, report destination in the brief

A node may name skills it uses, mapped to the agent file where the harness allows; the brief says where the final report goes. Why: the loop-engineering guide's two contract fields grooph lacks. Cost: small core change; verify the harness first.

A7 · spec amendment: sources

Add Gas Town, ralph, LoopX, Symphony, the Lloyd write-up and Ng's letter to the spec's sources and positioning table through an amendment, since the spec is frozen. Why: the spec's positioning table is what stops a future implementer rebuilding the wrong product; Gas Town belongs in it as "runtime and supervisor, not a designer". Cost: docs only.

A8 · design-skill sentences

When the ask is fuzzy, recommend spec-then-loop and say the human should close their decisions first (Wayfinder is the example). A human gate's question asks for the context the model lacks. Cost: skill text only.

A9 · done-intent marker

The lead writes a done-intent line before the final note, so a crash mid-completion is recognisable in the record. Why: Gas Town's cheapest good idea; the proving check can assert it. Cost: brief and check, no spend.

Declined

A pool node with runtime cardinality; persistent daemons or patrols with no exit; supervisory-only brakes without a budget; importing Gas Town formula files; grooph as scheduler or as memory store; any "until it beats the reference" stop. Each contradicts a decision already recorded (no runtime, every loop ends, brakes are real) and none has been needed by a run.

Attribution policy

A template that takes its shape or its name from someone's published work carries a credit with the person's name, the URL and one line on what was taken. Where the source is secondary (an article about a Reddit post) the credit says so. grooph's own text never claims the original author endorses the template, and the spec's rule stands: no claim that a graph beats a named product.

What this review does not settle

  • Whether any of the new templates helps on real work. Only a proving run and, later, a paired comparison can say.
  • Whether Claude Code subagents can be given skills by frontmatter today (A6 needs a check against the current docs).
  • Lloyd's actual prompt and schema, which I could not read; the template is built from the pattern as described.
