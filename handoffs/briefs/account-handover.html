What you lose, and why it costs nothing

Three published pages: the two gate briefs and the slice 0007 options launcher. A page belongs to the account that published it; the new account sees nothing at its URL.

Their substance was never only in them. Each is a phone-shaped restatement of docs/PROGRESS.md, docs/PLAN.md and the slice reviews, all of which travel with the clone. Nothing in the project reads them. Their sources now sit in handoffs/briefs/, so any of them can be published again from the new account, which mints a new URL to record beside the source.

Worth knowing: the share link inside the slice 0007 page carries its graphs in its own URL fragment and points at the app on GitHub Pages. That link keeps working after the switch. Only the wrapper page around it stops.

The switch, in order

  1. Nothing to prepare. The one thing the old account held that the new one cannot reach — those three page sources — is in the repository and pushed, as of this page.
  2. Sign in as the new account, in the same directory. No files move.
  3. Open a session in the clone and send the prompt below. It starts from AGENTS.md, which points at the current state.
  4. Check the tools answer: grooph --version, and /grooph-design offered in any project. If the clone has moved, re-run scripts/install-local.sh; it is idempotent and prints its plan before touching anything.
  5. Only if you want the briefs back: publish the files in handoffs/briefs/ from the new account and record each new URL in that folder's table.

The first prompt on the new account

You are the driver session for the grooph project at /Users/noir/Documents/grooph (published at github.com/ryanjosephkamp/grooph). This is a fresh Claude account; the previous one built slices 0001 through 0009.

Read AGENTS.md first, then docs/PROGRESS.md and docs/PLAN.md, then docs/HANDOVER.md for what did and did not carry over from the old account.

Then tell me, in a few lines: where the project stands, what is waiting on me, and what you would do next. Do not start implementation work until I confirm it.

Mode: execution. Effort: medium is enough to read in and report; the driver's own planning work wants high.

If the clone ever moves to another machine

  • Copy ~/.claude/projects/-Users-noir-Documents-grooph/ — the memory files and transcripts. Rename it to match the new path, dashes for slashes.
  • Copy ~/.claude/skills/ if you want this machine's hand-written skills.
  • Run gh auth login, then scripts/install-local.sh.
  • Expect nothing under a session scratchpad to survive. That is why AGENTS.md now says a page may only be published from a file the repository keeps.

The full recipe, including the routine that belongs to another project and must not be confused for grooph's, is in docs/HANDOVER.md.
