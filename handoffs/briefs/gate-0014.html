What the Operator found

It tried the end-of-turn push in a fresh cloud session. Nothing arrived, and nothing said why.

  • Cause. A cloud session starts with no branch checked out. The push had no name for its branch and stopped. The hook is built to stay silent, so it hid the error.
  • Effect. Three turns were lost without a sign. Its test runners never have a branch, so they would never have sent anything.
  • Its question. The hook settings are one file for every lane. Is one shared events branch safe with about ten sessions?

The Operator was right on every point. A hook that may not speak must still leave a trace.

What I changed

  • No branch, no loss. With no branch checked out, the events go to grooph-events-detached, a branch all such sessions share.
  • Every push leaves a record in the sandbox. grooph hooks status reads it: arrived, or failed and why, how many in a row, and when one last arrived.
  • A refused push goes again until its 45 seconds are nearly up. Before, it gave up after three tries.
  • A session on two branches is read as one. Before, it was counted twice.
  • The commit names no person. An events commit is now made as grooph, not with the session's git name and e-mail.
  • Sturdier in a sandbox. A remote that hangs is cut off cleanly without a terminal. The repository's own pre-push hook is not run. A link among the events is never followed.
