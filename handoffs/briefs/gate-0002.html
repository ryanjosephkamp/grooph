What was just completed

The core exists and is tested. packages/core holds the graph document types, a generated JSON Schema, the canonical form, the validator with all ten first-slice rules (each with a fixture that reports exactly its own code), and the Claude Code compiler. packages/cli exposes grooph validate | canonicalize | export. Core has zero runtime dependencies so it will run unchanged in the browser. CI runs on Node 22 and 24 and also checks that the compiler's output still matches the committed golden package byte for byte.

The riskiest claim was tested with a real run, and held. The exported review-loop package was dropped into a scratch project with a small task and a checklist, and Claude Code was started headlessly from the kickoff prompt alone. The lead dispatched a fresh builder, then a fresh critic with only the listed evidence (it wrote the diff and test output to files and handed the critic the paths, never a transcript). The critic re-ran the tests itself and failed round 0 on the one checklist item the task did not spell out. The builder fixed exactly that; the critic passed round 1; the "bar passed" stop fired; the lead halted at the merge gate and reported that it was waiting for a human, without inventing an answer. All nine run notes conform to the schema. One of the two approved runs is unused.

The implementer found one real hole, and it is now a decision. The critic must leave REVIEW.md behind but is denied file editing, so the lead filed the report for it. Fix: a new write-outputs capability (a node may write only the files it declares as outputs) and a warning rule, both scheduled for stage 3; the fixture stays as it ran until then. Seven smaller ambiguities the implementer flagged were resolved in the normative docs (round numbering, headless gates, workspace trust, tool-denial arithmetic, turn counting, evidence-as-files, the target registry).

Five tooling choices were promoted to a decision record so later slices inherit them rather than rediscover them.
