## Decisions made

- **A template opens in the app as its example.** `grooph share` refuses a template (`E_IS_TEMPLATE`), so the gallery's link is the `grooph share` envelope of the template filled with its slot examples, named "<title> (example values)". The page says so. The picture and glyph are drawn from the same document.
- **Links are compared by what they unpack to.** Compressors differ across machines and CPUs, so `--check` replaces each `#/open?d=…` by a digest of its unpacked envelope before comparing `index.json` and `docs/community.md`. The matrix runs Node 22 and 24, and this is what stops the check from failing on a different machine. Pictures are plain SVG and compare byte for byte.
- **Errors fail, warnings are listed.** A warning (for example `W_HOMOGENEOUS_CRITICS`) is shown on the page and in the report and does not block. A plain graph is validated for export; a template is validated twice (as itself, and filled with its examples for export). The community's own rules (file named for the id, a summary present, slots declared with examples, credits complete, `demo` a web link or a file under `experiments/` or the author's folder) print as `error  community  …` and have no code.
- **A folder holds documents and Markdown only**, directly in `community/<handle>/`; links, other file types, nested folders, a file over 256 KB and a handle that is not a handle are refused. The generated files must be regular files.
- **`community.yml` builds only core, installs with `--ignore-scripts`, and does not run at all** when the pull request changes any file outside `community/` (but `docs/community.md`): a first step with git only decides. The job summary then says so. This makes "nothing from a submission is executed" true even for a pull request that also edits the tooling.
- **Credits.** Only `literature-sweep` credits anything (the PRISMA 2020 statement, as the source of the search, screen and extract flow, with a note that it is not a systematic review). I could not name a source for the other two shapes without inventing one. If you know of work they come from, add it to `template.credits`.
- **Seed shapes.**
  - `literature-sweep`: searcher, screener, extractor, summarizer, and a frontier critic in its own context; a substantiated contradiction goes back to screening so it is treated like any other source. Loop: bar, 3 rounds, 14 dispatches.
  - `replication-check`: a reproducer that may not use the web and is told not to open the reported numbers (a brief, not a wall, and the description says so), a metric check, and a human gate at a disagreement. Loop: bar, 3 rounds, 8 dispatches.
  - `hypothesis-ratchet`: a proposer that cannot run anything and never opens the held-out folder, and a fast judge that runs the held-out command, keeps a change only if it strictly beats the last kept score, and records scores, never case contents. Stops in order: bar, diminishing returns (2 rounds, then on to Done), 5 rounds, 12 dispatches.

## Deviations

1. **`community.yml` runs `--report`, not `--check`.** The brief says "runs the script's check". `--check` also fails when the generated gallery files are stale, and a fork's pull request cannot be expected to regenerate them. `--report` does the document half of the check, plus one thing `--check` cannot say: it fails when a generated file the pull request touches is not what the generator makes (a hand-edited `docs/community.md`, say). It reports stale files the pull request leaves alone and does not fail on them.
2. **`ci.yml`'s step has an `if:`.** It runs on pushes and on pull requests from the same repository, and not on fork pull requests, for the same reason. A merge that leaves the gallery stale turns the push to `main` red, which is the owner's cue to run the script. Say so if you would rather it ran everywhere.
3. **The folder rules are stricter than the brief** (no files but documents and `.md`, no links, no nested folders). The review found that an `.svg` or `.html` dropped in an author's folder would otherwise be stored unread and unreported.
