## Objective

Study one could not separate the graph's design from its record (the derived prompt kept the roles) and could not make a loop turn (every task passed at round 0). Decision 0012 revised the protocol: a fourth arm with no roles, tasks built so a strong builder's first pass fails, a held-out suite per project, the round-0 pass probability pre-registered, the runner's clock for every arm, and task files that never name grooph. This slice runs study two under that protocol on the two templates whose loops turned in the proving ground plus a harder review-gate task, and, because it shares the same sessions and evidence discipline, carries the two small re-proofs slice 0020 lists.

## Success criteria

1. **Runner at protocol v2.** `scripts/compare.sh` gains arm **D** (task, acceptance material and test command only: no roles, routing, loop or briefs; the prompt is generated by `compare-prompt.mjs` from the task folder alone, committed as `prompt-D.md`); the derived B prompt's gate sentence reads "stop and report when you reach this point; do not proceed past it"; wall time is the runner's clock for every arm; `--status` and the summary handle four arms. Unit tests updated. Dry runs for all four arms before any spend.
2. **Three projects, each built to fail a first pass**, pre-registered before the first run with the expected round-0 pass probability and why the task should not pass (protocol §7):
   - `heterogeneous-critic`: a new task whose held-out suite settles at least three points the visible spec leaves open in ways a careful builder would guess differently (as the proving task did with whitespace and fractions), sized so a round-0 pass is unlikely (state the probability);
   - `taste-polish`: a rendered artifact (text report or SVG) against a held-out reference with at least three properties only a side-by-side shows; the reference is named to the critic only;
   - `review-gate`: a harder task than study one's: the checklist holds two items the task text does not state, and the held-out suite covers both.
   Task files never name grooph's folder or tools.
3. **Runs.** Four arms × two replicates per project in the order A1 B1 C1 D1 A2 B2 C2 D2; every invocation a ledger line; the one retry rule; a cut-off at the per-invocation cap is scored, not retried. Held-out suites are named to a reviewer in A, B and C exactly as the template names them to its critic, and to nobody in D.
4. **Scoring and judging** as in study one (identical scorer; one blind judge per project over eight candidates; letters never A–D; mapping kept apart).
5. **Write-ups** per protocol §9 with the required line, plus one new required line: **did a loop turn, and did the turn change the result**. `experiments/comparisons/README.md` gains a study-two section and index rows; `compare-summary.mjs` prints both studies.
6. **The 0020 re-proofs** under the proving ledger: (a) `gauntlet-decomposed` v2 on its existing task, `run/` moved to `run-1/` first, reporting whether the planner now names the cut without copying it and whether `e-critic-fail` fires; (b) `patrol-pulse`: rename the investigator's output from `FINDINGS.md` to `PULSE.md` in the pattern (version 2, and `expect.json`), regenerate the index, re-run and re-check with `run/` moved to `run-1/`.
