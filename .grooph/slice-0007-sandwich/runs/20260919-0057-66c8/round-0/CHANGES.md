## By success criterion

1. **Green from a fresh clone.** No dependency changes, so the lockfile is untouched. `vite.config.ts` raises `chunkSizeWarningLimit` from 700 to 800 KB because the bundled pattern library adds about 97 KB raw (15 KB gzipped). That limit only controls a warning.
2. **Template library.** `src/doc/templates.ts` bundles `patterns/*.grooph.json` at build time through `import.meta.glob(..., { query: "?raw" })`, so the app makes no network request. The new `#/templates` screen is reached from a new "Templates" button in the library. It has "Yours" (when it has templates) and "Built-in". Each row shows the title, a fragment badge, Use when, Not for and profile chips. `#/templates/<built-in|yours>/<id>` opens the template read-only in the existing `GraphViewer`, which gained `issues`, `about` and `bar` props. The viewer opens with an About sheet: summary, profile, when and not-for, and the slots with ask, `{{key}}` and example.
3. **Use.** The form at `#/templates/<source>/<id>/use` asks for a graph name, then one field per slot: the label is the slot's `ask` and the placeholder is its `example`. Any slot may be left empty. On submit it calls core's `instantiate` with only the filled values and an id that is unique on the device, saves the graph and opens the editor. An empty slot shows as `E_UNFILLED_SLOT`. Tapping that issue highlights the nodes it points at. The editor title now highlights too, for slots at graph level.
4. **Insert.** The Add sheet has a new "Insert a template" entry. It lists fragments, then whole graphs, yours before built-ins. The person picks one, can fill its slots, and can give an id prefix. Core's `insertFragment` does the insert as a single undo step. The id map (`from → to`, renamed ones in bold) shows once in the sheet and is gone after Done. The inserted nodes are highlighted, set as the selection, and brought into view.
5. **Save as template.** The Graph panel has a new "Reuse" section with a "Save as template…" button. The form offers Whole graph or Selected nodes. For selected nodes, node chips are preselected from the current selection: the last node tapped, or the last insert. The form takes id, title, summary, when to use and an optional not-for. The profile starts from core's estimate, labelled "Estimated from the graph", and can be corrected per axis. Saving calls core's `extractTemplate`. User templates live in a new IndexedDB store, `templates`: the DB goes to version 2, and graphs from version 1 are kept. Saving over an existing id asks before replacing, and a replacement bumps the version. The About sheet of one of Yours can download the canonical `<id>.grooph.json` and delete the template (with a confirm step). Importing a file that has a `template` block offers "Add to Yours", "Open it as a graph" or "Cancel". If the id exists, the offer becomes "Replace yours" with the next version number.
6. **Undo and redo.** `DocStore` keeps a stack of whole documents, bounded at 100 steps. Typing merges into one step when edits come from the text controls in `fields.tsx` (wrapped in `typing()`), touch at least one of the same text fields, and fall within 1.2 s of each other. Taps, drags, inserts and deletes are always separate steps. The toolbar has Undo and Redo buttons. The keyboard shortcuts are Cmd/Ctrl+Z, Shift+Cmd/Ctrl+Z and Ctrl+Y. The stack survives closing the sheet but not a reload. Deleting a node, an edge or a loop shows a toast ("Deleted Critic" with Undo) for 6 s. Its Undo only acts while that delete is still the last edit.
7. **Storage persistence.** `src/store/persist.ts` hooks the first successful IndexedDB write. It calls `navigator.storage.persist()` once per device and stores the answer in `localStorage` under `grooph.persistence`. The editor and the library show "Storage kept" or "Storage not guaranteed … Export, then Download graph" until the person taps "Got it", and never again. The editor shows the notice in its own grid row, so it covers no part of the canvas.
8. **Toolbar and sheet.** At phone width, when the sheet is open the toolbar docks as a full-width row between the canvas and the sheet: the stage becomes a flex column with the React Flow pane above the toolbar. It floats as before when there is no sheet, and on wide screens. `ensureVisible` now measures the toolbar and does not assume a fixed 84 px.
9. **Rename warning.** "Download package (.zip)" records `exported: { id, at }` on the graph record. Autosave now saves through a ref to the record, so that field is not lost. A rename that changes an id that still follows the name, away from the exported id, shows a warning in the Graph panel and in the library's rename form. It names `.grooph/<old>/` and `.grooph/<new>/` and offers "Keep the old id".

## Implementer's choices worth a look

- The typing heuristic: an explicit `typing()` wrapper in the shared field controls, not a pure time window. This way quick taps on a segmented control stay separate steps.
- "Exported from this device" means a package zip was downloaded. Downloading the `.grooph.json` or copying the kickoff prompt does not count.
- `patterns/README.md` is generated, so the new sidecar is not listed there. The generator's `--check` passes.
- Not done, by design: remote registries, copy/paste, bulk multi-select on the canvas. Selected nodes are chosen with chips in the Save form instead.
