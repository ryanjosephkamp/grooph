# Spec amendments

`capability-spec.md` is frozen as received on 2026-09-17. It changes only here. Each amendment names the section it touches, the new rule, and why. When the spec and any other document disagree, the spec plus this file wins.

| ID | Date | Section | Amendment | Why |
|---|---|---|---|---|
| A-001 | 2026-09-17 | §7.4, §16 | Claude Code is the first compile target; Codex is the second, started only after the Claude Code path works end to end. | Owner's harness priority. |
| A-002 | 2026-09-17 | §5.3, §5.5 | A **loop** is a first-class object in the graph document (members, back-edge, bar, stops). Stops and bars attach to loops, not to edges. | Makes "every cycle has a stop" a mechanical check: every detected cycle must be covered by a loop object with at least one valid stop. |
| A-003 | 2026-09-17 | §5.2 | Model preference is a harness-neutral **tier** (`frontier`, `strong`, `fast`) plus optional per-harness pin; effort is `low`, `medium`, `high`, `max`. Each compile target ships a profile mapping tiers to current model names. | Answers the §17 open question on vendor renames; keeps the core harness-neutral. |
| A-004 | 2026-09-17 | §8 | The executive agent lives in the harness (Claude Code or Codex) and drives grooph through a skill plus the MCP server or CLI. grooph itself makes no LLM calls. | Owner decision 2026-09-17. Removes keys, inference cost and a backend from the platform. |
| A-005 | 2026-09-17 | §6 | Node positions live in a separable `layout` section of the document that models may ignore. Graphs without layout get automatic layout in the human view. | Keeps semantic diffs clean; agent-built graphs carry no coordinates. |
| A-006 | 2026-09-17 | §9 | A package has two delivery modes: **files** (native harness units placed into a repo) and **paste-only** (one prompt that writes the same files, for sessions where only pasting is possible). | Phone-first authoring. |
| A-007 | 2026-09-17 | §11 | v1 harness connection is a **file contract**: the package instructs the run to append structured run notes to a known path; grooph imports that file. Live append through MCP is a later addition. | Avoids instrumenting harness internals on day one, as §11 already prefers. |
| A-008 | 2026-09-18 | §4.4, §5.7, §11 | Graphs are **adaptive by default**. During a run the lead may amend a run-local working copy of the graph (add or re-brief nodes, add edges and loops, change tiers). Every amendment is recorded as a note and shown in the progress log, the amended document must still validate, and brakes are not adaptable: gates, approvals, irreversible markers, budget and max-iteration stops, a bar's acceptance, critic isolation and the adaptation level can be tightened by the lead but never loosened. The source document is never written by a run; the human adopts or discards the working copy afterwards. `adaptation: "propose"` restores the spec's original default and `"fixed"` forbids deviation. | Owner decision after the first phone session: over-prescribed graphs that cannot bend are a bigger risk than visible, validated adaptation. The spec's concern was *silent* rewrite and loss of the human brake; both protections are kept. This also updates the project's original hard rule that live graph mutation is human-gated: mutation of brakes stays human-gated, the rest is visible and default-on. |
| A-009 | 2026-09-18 | §7, §8, §16 | **Agents are the primary authors.** The human surface is for review, editing and template reuse; building from a blank canvas stays possible but is not optimised. The executive path (§8) and templates (§10) are prioritised ahead of the remaining manual-authoring conveniences in §7 (copy/paste, bulk spawn, grouping), which stay in scope for later. | Owner feedback: manual authoring works but is slow, and that is acceptable because agents will build most graphs. |
| A-010 | 2026-09-21 | §14, §18 | **Sources and positioning additions.** §18 gains: Gas Town (github.com/gastownhall/gastown), Geoffrey Huntley's ralph loop (ghuntley.com/ralph), OpenAI Symphony (github.com/openai/symphony), LoopX (github.com/loopx-project/loopx), the Lloyd heartbeat-orchestrator write-up (explainx.ai, 2026-08-14), Andrew Ng's three loops (The Batch, 2026-06-30) and Matt Pocock's Wayfinder (github.com/mattpocock/skills). §14 gains a row: **multi-session supervisors** (Gas Town, Symphony) run and supervise many harness sessions over durable work items with retries and merge queues; this spec designs the graph one session runs and has no runtime, so their vocabulary (roles, merge queue, patrol) is compile-target material, not a product to rebuild. | Decision 0010: prior art is credited and adapted within the spec; the positioning table is what stops a later implementer rebuilding a supervisor. |
| A-011 | 2026-09-30 | §2, §5.1, §6, §14 | **Operation maps.** A second kind of document, the *operation map*, shows work that spans sessions. Its nodes are harness sessions (harness, account, machine, model, role); its edges are handoffs, each naming its carrier (a repository branch or pull request, a harness's session-to-session message, a scheduled message, a review page, a person carrying a prompt); its lanes group sessions by machine and account; a session may point at the loop graph it runs. A map is drawn and validated and is **never compiled, exported as a package or run**: the non-goals of §2 stand, grooph has no runtime, and the multi-session supervisors named in A-010 are still not rebuilt. **The graph document is unchanged.** A graph remains one session and its subagents, every existing graph loads as before, and a map is a separate document with its own version key (`groophMap`) and schema. Shape and rules: `docs/operation-map.md`. | Owner's brief of 2026-09-30 (decision 0014): his work now spans an Operator session steering a dozen cloud sessions, a second project, Codex on the Mac and this account, joined only by repositories and by him carrying prompts. The graph cannot show that without breaking the one-session contract every package relies on, so the map sits beside it rather than inside it. §14's "session dashboards" row said such a view was useful later; this is the authored half of it, and it stays a document, not a dashboard with a backend. |
| A-012 | 2026-09-30 | §11, A-007 | **Hook-written session events.** The file contract of A-007 gains a second file, written by the harness's hooks and not by the lead: one JSON line when a session or a subagent starts or stops (and, if asked, when a tool call finishes), appended to `.grooph/events/<session id>.jsonl`. It holds ids, names and times, never a prompt, a tool's input or result, or a reply. The hook prints nothing and always exits 0, so it observes and cannot steer; nothing in a package depends on it, the lead's brief is unchanged, and a run without it is as before. grooph reads these files to show which subagents are running, in Claude Code and in Codex, for a run or for any session, and still starts and supervises nothing. Shape, what each harness tells a hook, and the sources: `docs/subagents.md`. | Owner's brief of 2026-09-30 (decision 0014): he wants to watch subagents as they run, in both harnesses. §11 already allows a harness connection for notes and says not to instrument every internals API; a hook is the harness's own published way to be told, and A-007 named live append as a later addition. Keeping the lead's brief unchanged keeps this an observation: the change that lets a lead write fewer notes because a hook writes them (slice 0021) still needs its own proving run. |
| A-013 | 2026-10-01 | A-011 | **People on an operation map.** A-011 made a map's nodes harness sessions and let a person appear only as a carrier between two of them. A map may now also name **people** (`people`: an id, a name, a role), and a handoff may start or end at one. A carrier kind is added for what reaches a person without anyone carrying it: a **notification** (a push notification, an e-mail). A handoff that starts at a person moves only when that person does it, and is said so with the hand-carried ones. Nothing else moves: a person is not a session, has no lane, harness or model, and is never compiled or run; the graph document is unchanged. The change is additive within `groophMap: 0`: every map written for 0.1.0 loads and validates as before. A map that draws people needs this version of grooph to read it (0.1.0 reports an unknown key and handoffs that end nowhere). Shape and rules: `docs/operation-map.md`. | The Operator session that runs the owner's operation, after drawing the real map (2026-10-01): the owner is its hub. He marks the review pages, reads the routines' notifications and carries three prompts, and the map could show him only as a `person` carrier between two sessions, which hides that all three pass through one man. The same answer asked for a mark on a session that wakes itself on a schedule; that is a drawing of what the document already says (a scheduled handoff from a session to itself) and needs no change to the contract. |
| A-014 | 2026-10-01 | A-012 | **Sending the events, and reading a stale record honestly.** A-012's hook writes a session's events to a file in its own clone. Two things are added around it, and the hook itself is unchanged: it still appends one line, prints nothing, exits 0 and reaches no network. (1) The events may be sent to a git branch that holds nothing else (`grooph events push`), and, **only when the owner of a project asks for it at install** (`--push`), a second hook does that at the end of every turn, in the background. That second hook keeps the same promises towards the session: it prints nothing, always exits 0, and returns nothing a harness reads. What it adds is a write outside the clone, to a branch that may hold only events: a branch with anything else on it is refused. (2) A record is only as fresh as its last line, so a reader does not call a session working when it has said nothing for half an hour: it says when the session was last seen. grooph still starts and supervises nothing. | The Operator session, after running the hook in a cloud lane (2026-10-01): a push is a snapshot, and a session cannot send what it writes as it stops, so a lane's last turn and its end never left the sandbox and the lane read "working" for good. Sending at each turn's end is the only way that line leaves; it uses the session's right to push, so it is asked for, not assumed. The reader's rule costs nothing and is right whether or not anything is sent. |
| A-015 | 2026-10-02 | A-014 | **A push that fails is on record, and an events branch names no person.** A-014 let a second hook send the events at a turn's end and promised it prints nothing and always exits 0. That promise stands; four things are added. (1) **Where the events go when no branch is checked out:** to one branch every such checkout shares (`grooph-events-detached`), so nothing is dropped for want of a name. (2) **A record of the push:** the push writes how it went into one small file beside the events (`.grooph/events/.last-push.json`): that it began, and then whether it arrived, on which try, or what git said. The file is never sent, is not an event, and is read by `grooph hooks status` and `grooph sessions`, never by a harness: the hook stays silent towards the session and stops being traceless. (3) **Sharing a branch:** many sessions may send to one events branch; a push that another session beat is made again on top of it for as long as its time allows, and a session whose file is on two branches is read as one session. (4) **An events commit is made as `grooph`,** not with the session's git identity: the branch holds ids, the names of agents and times, and nobody's name or e-mail address. | The Operator's trial of the turn-end push (2026-10-02): a cloud session starts with no branch checked out, the push threw for want of a name, and the hook swallowed it by design, so three turns were lost without a sign. It also asked whether about ten sessions may share one branch, since a repository's hook settings are one file for every lane. Measured the same day: ten pushes at one moment to one branch on GitHub all arrived, the last after 25 seconds on its tenth try; and the first attempt was refused by GitHub because the commits carried the owner's private e-mail address, which is how (4) was found. |
| A-016 | 2026-10-03 | A-014, A-015 | **What leaves a machine is less than what it keeps, and a turn's end sends its own session's files.** The push sends each event line as the hook wrote it, with two changes: a folder (`cwd`) is sent as its last name, not its path, and the path of a subagent's transcript is not sent. Only whole lines are sent. The files on the machine are unchanged, and A-012's hook still writes what it wrote. At a turn's end the push sends a file only if it has to do with the session whose turn ended: its own file, a file with a line written since that session began, or a file the branch already holds. It learns which session from the harness's hook input. Told nothing it can use, it sends every file, as by hand. A reader counts a sent copy and the line it came from as one event. | The Operator's second trial (2026-10-03): two fresh cloud sessions each sent a file from a session of October 1, which the environment had kept from an earlier sandbox; sent again, it read as theirs. And the events branches of a public repository are public: a path names a machine's folders and, on a person's own computer, the person. A reader elsewhere has no use for either path. |
| A-017 | 2026-10-03 | A-014 | **A turn that is open is sent as open.** A-014 let the second hook send the events at the end of every turn. Installed with `--push`, it now sends them at three moments, all in the background and all with A-014's promises (nothing printed, exit 0, nothing a harness reads back, only an events-only branch): at the end of a turn; at its start; and in passing on a finished tool call that the event hook records, when the last push was ten minutes ago or more. A push at a turn's start or end waits for one under way and then sends; one made in passing gives way. The push script also gains a way to say what is in a project (`--status`): it reads, runs the event hook once into a scratch folder, sends nothing and changes nothing. | The Operator, after putting the hooks on its lanes (2026-10-03): a lane half an hour into a long turn read "last seen 32 min ago, waiting then", since nothing had been sent since its last turn ended; and one lane that merged the hooks in mid-session never recorded, with nothing to say so from inside a sandbox that has no grooph. |
