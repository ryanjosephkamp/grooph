# Compile target: Codex

How the package contract in [`graph-ir.md` §5](../graph-ir.md#5-package-contract) maps onto Codex's native units. Researched against the OpenAI Codex documentation on 2026-10-04; CLI **0.160.0** help was read, but the package has not been run in Codex. The tool surface and model availability vary by client, account and workspace. Recheck the linked sources before changing this mapping.

Every row is marked **[doc]** when the current official documentation specifies it, **[seen]** when the cited local CLI or repository observation confirms it, or **[unknown]** when neither establishes the behavior. A row can carry more than one mark. “Documented” does not mean that the package has exercised the behavior in a proving run.

## Package layout (files mode)

```text
<project>/
  .grooph/<graph-id>/
    graph.grooph.json        canonical source document
    LEAD.md                  lead brief, named by KICKOFF.md
    MAPPING.md               graph piece to file mapping and hand-editable values
    KICKOFF.md               the prompt/command to start the fresh lead session
    runs/                    created by a run
      <run-id>/PROGRESS.md
      <run-id>/notes.jsonl
      <run-id>/graph.grooph.json   the run's working copy
  .codex/agents/<graph-id>--<node-id>.toml
```

The target writes each non-lead agent node as a project-scoped custom agent TOML file. Its required fields are `name`, `description`, and `developer_instructions`; optional fields include `model`, `model_reasoning_effort`, `sandbox_mode`, and other supported Codex configuration keys. The TOML filename need not match `name`, but matching it is the documented convention. **[doc]** [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)

This package does not install a root `AGENTS.md`, `.codex/config.toml`, or user-level setting. `KICKOFF.md` names `LEAD.md` explicitly; Codex's normal project guidance discovery remains the repository's own responsibility. Project-scoped `.codex/` configuration is loaded only for a trusted project, so the user must trust the checkout for these custom agents to be discovered. **[doc]** [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [Configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference)

## Lead brief and run control

`LEAD.md` follows [`graph-ir.md` §5](../graph-ir.md#5-package-contract): it tells the main session to create a run folder, copy the canonical graph to its working copy, initialize `PROGRESS.md`, route nodes, enforce stops, write run notes and halt at gates. `KICKOFF.md` tells a fresh `codex exec` session to read that brief. The package names the lead model and effort; the human selects them when starting the command. The lead does not rewrite root guidance or shared Codex configuration.

A human gate is recorded before asking the human. A headless session cannot wait for an interactive answer, so it returns the halt note and session id. The human then resumes that same session with the explicit decision. A later independent run starts with a fresh `codex exec` and a new run id; it does not answer the earlier gate.

The human instructions, graph routing, node scope and gates are package behavior. The sandbox limits command execution, but it does not enforce per-artifact ownership, evidence allowlists, graph budgets, loop stops or a gate decision. The lead's output-scope instructions do not replace the sandbox or a human review.

The mapping does not claim that `codex exec` will obey an untrusted project's custom-agent files, that an arbitrary graph skill exists, that CLI dispatch preserves no history unless `fork_turns: "none"` is available, that a project agent edit reloads live, or that the lead reliably halts/resumes on every gate. The Codex proving run must establish those run behaviors before they are reported as seen.
